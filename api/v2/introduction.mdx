API v2 is served at `https://api.meteroid.com/api/v2`, beside v1, with the same API keys. v1 is frozen: it keeps working, but new features ship in v2 only. New integrations should use v2.

## Authentication

Send your API key as a bearer token:

```bash
curl https://api.meteroid.com/api/v2/plans \
  -H "Authorization: Bearer $METEROID_API_KEY"
```

## Versions

Send `Meteroid-Version: YYYY-MM-DD` to pin the shape your integration was written against. Meteroid answers with the latest version published on or before that date, and echoes it in the `Meteroid-Version` response header. Without the header, you get the first v2 version, `2026-12-01`.

## Identifiers and codes

- Ids are prefixed by their resource: `plan_…`, `prd_…`, `sub_…`, `cus_…`, `inv_…`. Paths also accept the UUID form.
- Plans, products, add-ons, product families, metrics, coupons, features, rate cards and credit units have a **code** you choose (`pro`, `api-calls`). Every catalog path takes the id or the code: `GET /api/v2/plans/pro`.
- A customer is named by its id or by its alias written `ext:<alias>`. A subscription by its id or by the `external_id` you gave it.

## Money and quantities

- A price or a rate is a decimal string in the currency's major unit: `"49"`, `"0.0015"`.
- An amount billed (an invoice total, a minimum) is an integer in minor units next to its `currency`: `{"amount": 4900, "currency": "EUR"}`.
- Quantities are decimal strings.

## Lists

Lists answer `{data, next_cursor, has_more}`. Pass `limit` (1 to 100, default 20) and `after=<next_cursor>` for the next page. Cursors are opaque.

## Changes

- `PATCH` takes a JSON merge patch: a field left out is unchanged, `null` clears it.
- Every change to a subscription has a `…/preview` sibling taking the same body and writing nothing: it answers the documents the change would issue and the subscription as it would read after it.

## Idempotency

Send an `Idempotency-Key` header with any `POST`. A retry with the same key and body answers the first response, with `Idempotent-Replayed: true`. Writes that bill (creating a subscription, changing its plan, seats, levels or add-ons, cancelling it, recording a payment) require one. Keys are kept 24 hours.

## Errors

Errors are [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problems, `application/problem+json`:

```json
{
  "type": "https://docs.meteroid.com/api/v2/errors/validation_failed",
  "title": "A field of the request is refused",
  "status": 422,
  "code": "validation_failed",
  "detail": "…",
  "errors": [{ "path": "/charges/0/prices/0/amount", "code": "invalid", "message": "…" }],
  "request_id": "…"
}
```

`code` is stable: branch on it, not on `title` or `detail`. `path` is a JSON pointer into your request. Send `X-Request-Id` to have it echoed as `request_id`. See [Errors](/api/v2/errors) for every code.
