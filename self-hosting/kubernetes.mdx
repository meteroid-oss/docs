The Helm chart deploys the four Meteroid processes: the API, the worker, the metering API and
the web app. It does not deploy PostgreSQL, ClickHouse, Kafka or object storage: you provide
them, managed or operated in your cluster.

## Prerequisites

- **PostgreSQL 18** with the [`pgmq`](https://github.com/pgmq/pgmq) extension available. The
  migrations run `CREATE EXTENSION pgmq`. Meteroid publishes PostgreSQL images that include it:
  `ghcr.io/meteroid-oss/meteroid-postgres:18.3-cnpg` for
  [CloudNativePG](https://cloudnative-pg.io/) and `ghcr.io/meteroid-oss/meteroid-postgres:18.3-standard`.
- **Kafka**. The chart's defaults expect SASL/SCRAM-SHA-512 authentication (`global.kafka.*`).
  Create the `meteroid-events-raw` topic, unless your brokers create topics automatically.
- **ClickHouse** with Keeper (or ZooKeeper). The migrations create `Replicated*MergeTree` tables
  `ON CLUSTER` the cluster named in `global.clickhouse.clusterName`, and the ClickHouse user needs
  the `named_collection_control` privilege.
- **S3-compatible object storage** (`global.objectStore.*`).
- **Traefik**, for the `IngressRoute`s the chart creates by default. With another ingress
  controller, set `ingress.useIngressRoute: false` to get a standard `Ingress`.

Optional: Redis (`global.redis.url`), which shares rate limits and caches across replicas, and an
SMTP server (`global.smtp.*`).

## Install

<Steps>
  <Step title="Write your values">
    Create a `values.yaml` with at least the URLs, hosts, secrets and service addresses of your
    installation (see [Values to set](#values-to-set)):

    ```yaml values.yaml
    global:
      publicAppUrl: "https://billing.example.com"
      publicApiUrl: "https://billing-rpc.example.com"
      publicRestApiUrl: "https://billing-api.example.com"

      secrets:
        databaseUrl: "postgres://meteroid:<password>@postgres:5432/meteroid"
        jwtPrivateKey: "<random string>"
        internalApiSecret: "<random string>"
        secretsCryptkey: "<exactly 32 characters>"
        kafka:
          password: "<password>"
        clickhouse:
          password: "<password>"

      kafka:
        bootstrapServers: "kafka:9092"
      clickhouse:
        httpAddress: "http://clickhouse:8123"
        tcpAddress: "clickhouse:9000"
      objectStore:
        uri: "s3://meteroid"

    ingress:
      hosts:
        - host: billing.example.com
          paths:
            - { path: /, pathType: Prefix, service: web, port: 80 }
        - host: billing-rpc.example.com
          paths:
            - { path: /, pathType: Prefix, service: api, port: 50061 }
        - host: billing-api.example.com
          paths:
            - { path: /, pathType: Prefix, service: api, port: 8080 }
      tls:
        - hosts: [billing.example.com, billing-rpc.example.com, billing-api.example.com]
          secretName: meteroid-tls
    ```

    Generate `jwtPrivateKey` and `internalApiSecret` with `openssl rand -hex 32`, and
    `secretsCryptkey` with `openssl rand -hex 16`.
  </Step>
  <Step title="Install the chart">
    ```bash
    helm install meteroid oci://ghcr.io/meteroid-oss/charts/meteroid --version 2.0.0 -f values.yaml
    ```

    The chart version is the Meteroid version: chart `2.0.0` runs the `2.0.0` images. Releases
    are listed on the
    [package page](https://github.com/orgs/meteroid-oss/packages/container/package/charts%2Fmeteroid).
  </Step>
  <Step title="Create the first account">
    Once the pods are ready, open the web app at `publicAppUrl` and sign up. The first account
    creates the organization; after it, sign-up is closed and teammates join by invitation.
  </Step>
</Steps>

<Warning>
  `global.secrets.secretsCryptkey` must be exactly 32 characters, set before the first start, and
  never changed. It encrypts the credentials of your connectors (payment providers, accounting,
  CRM) stored in PostgreSQL: with another key, Meteroid can no longer read them.
</Warning>

## Values to set

See the chart's `values.yaml` for every value. The ones most installations set:

| Value | Description |
|---|---|
| `global.publicAppUrl`, `global.publicApiUrl`, `global.publicRestApiUrl` | Public URLs of the web app, the gRPC API (called by the browser) and the REST API. |
| `ingress.hosts`, `ingress.tls` | The same hosts, and their TLS secret. |
| `global.secrets.existingSecretName` | A Secret you manage, holding the keys listed below. Leave empty to have the chart create it from `global.secrets.*`. |
| `global.secrets.databaseUrl`, `jwtPrivateKey`, `internalApiSecret`, `secretsCryptkey` | Required. |
| `global.kafka.*`, `global.clickhouse.*`, `global.objectStore.uri` | Kafka, ClickHouse and object storage. |
| `global.secrets.kafka.password`, `clickhouse.password`, `redis.password` | Their credentials. |
| `global.secrets.objectStore.accessKeyId`, `secretAccessKey` | Object storage credentials. |
| `global.smtp.host`, `from`, `customerFromAddr`, `replyTo` | Email delivery. `from` is required once `host` is set. Credentials: `global.secrets.smtp.*`. |
| `global.redis.url` | Optional Redis. |
| `global.webhooks.*` | Outgoing webhook delivery, for example an egress proxy. |
| `<component>.resources`, `<component>.autoscaling` | Unset by default. CPU autoscaling needs CPU requests. |
| `<component>.extraEnv` | Extra environment variables, as a list of `name`/`value` entries, for any setting of the [configuration reference](/self-hosting/configuration). |

The components are `api`, `worker`, `metering` and `web`.

### Secret keys

When you provide your own Secret with `global.secrets.existingSecretName`, the chart reads these
keys from it:

| Key | Required | Content |
|---|---|---|
| `database-url` | Yes | PostgreSQL URL |
| `jwt-private-key` | Yes | Session signing secret |
| `internal-api-secret` | Yes | Secret shared by the Meteroid processes |
| `secrets-crypt-key` | Yes | 32-character encryption key |
| `license-key` | No | Offline license |
| `kafka-password`, `clickhouse-password`, `redis-password` | No | Service credentials |
| `aws-access-key-id`, `aws-secret-access-key` | No | Object storage credentials |
| `smtp-username`, `smtp-password` | No | SMTP credentials |
| `oauth-google-client-id`, `oauth-google-client-secret` | No | Sign in with Google |
| `oauth-hubspot-client-id`, `oauth-hubspot-client-secret`, `oauth-pennylane-client-id`, `oauth-pennylane-client-secret` | No | HubSpot and Pennylane connectors |

### The worker

The worker's values are under `worker`: image, replicas, resources and its own settings.

<Note>
  The chart used to call it `scheduler`. Chart 2.0 still reads a `scheduler:` section for one
  release; rename it to `worker:` in your values.
</Note>

### License

The chart runs the official images, which are free without a license (see
[Editions](/self-hosting/editions)). To license the installation:

| Value | Description |
|---|---|
| `global.secrets.licenseKey` | An offline license (`license-key` in an existing Secret), passed as `LICENSE_KEY`. |
| `global.licenseServerUrl` | The license server an online license refreshes against. Defaults to `https://api.meteroid.com`; set it only if you were told to. |
| `global.adminOrganizationId` | On an installation with several organizations, the organization whose admins manage the license. |

You can also activate a license online from **Settings → License** in the app, with no change
to your values.

### Telemetry

The installation sends one [anonymous report a day](/self-hosting/telemetry). To turn it off:

```yaml values.yaml
global:
  usageTelemetry: false
```

## Upgrade

Back up the database, then upgrade the release to the new chart version:

```bash
helm upgrade meteroid oci://ghcr.io/meteroid-oss/charts/meteroid --version 2.0.1 -f values.yaml
```

The new pods run the migrations as they start. Until the last old pod is replaced, the old
version runs against the new schema and may fail some requests.

Leave the `image.tag` values unset: they default to the chart's version, so the chart version
alone decides what runs. If your values set `image.repository` to an image name ending in `-ee`,
remove it: those names are deprecated, still published for 2.0, and will stop.

Coming from an earlier public release? Read [Upgrading to 2.0](/self-hosting/upgrading-to-2-0)
first: the chart changed.
